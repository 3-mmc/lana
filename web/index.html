Providers configured on the machine serving this page
Providers come from providers.json beside serve.py. API keys stay on that machine: this page is told only whether a key is present. Requests are proxied, so there is no CORS to configure and no key in the browser. Copy providers.example.json to start.
Recognisers in this app
Built-in models keep your recordings on this computer. They run on this machine's own processor, work offline once downloaded, and never send audio, transcriptions or annotations anywhere. That is usually what an ethics board or data-protection plan needs to hear about recordings of identifiable speakers.
What Lana does connect to, exactly
  • Hugging Face, when you click Download: the model file, once. Nothing about your recordings is sent.
  • GitHub, a few seconds after start: whether a newer Lana exists. Nothing about your recordings is sent.
  • A cloud recogniser or speech server, only if you add one below and then run it: the recording you run it on goes to that service, under that service's terms. Such recognisers are marked sends audio to … wherever you choose them.
  • No accounts, analytics or usage statistics. Annotations are saved in Lana's own folder on this computer.

not checked
Anything exposing POST {base}/v1/audio/transcriptions in the OpenAI shape. A cross-origin endpoint must send Access-Control-Allow-Origin, which is the usual reason this mode fails where the proxied one works. If the endpoint also serves {control}/progress, {control}/partial and {control}/cancel, you get live progress, tiers that fill while the job runs, and a working Stop button.
